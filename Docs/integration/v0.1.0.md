# Integration guide — v0.1.0

Baseline public surface for the first tagged **iOS** SDK release.

## Who should read this

Host apps integrating Diverge SDK for the first time via Swift Package Manager.

Android: see [Diverge-SDK-Android](https://github.com/askdiverge/Diverge-SDK-Android).

## Public API

The product is `AIConversation`. Its entire public surface is `AIChat`, its nested `Configuration`,
and `ConversationFlow`.

### Create a chat

```swift
import AIConversation

let chat = AIChat(
    .init(
        tokenProvider: { try await myAuth.sessionToken() },
        resetConversation: { try await myAuth.newSessionToken() },
        deleteData: { try await myAuth.deleteVisitorData() }
    )
)

chat.makeView()                                  // SwiftUI
present(chat.makeViewController(), animated: true) // UIKit
```

Or register a shared configuration once at launch and mint instances from it. The two forms coexist:
a shared configuration for an app-wide chat, direct configuration for chats scoped to one screen.

```swift
AIChat.configure(.init(tokenProvider: …, resetConversation: …, deleteData: …))
let chat = AIChat()
```

You don't have to store the `AIChat` instance unless you explicitly want the session to outlive the
presentation lifecycle.

### Configuration

| Parameter | Required | Purpose |
|-----------|----------|---------|
| `tokenProvider` | yes | Supplies a session token on demand. The SDK never mints or stores credentials. |
| `resetConversation` | yes | Ends the conversation and returns a fresh session token. |
| `deleteData` | yes | Ends the session and wipes visitor data (typically `DELETE /api/v1/chat`). The Privacy & Data sheet also offers **Download my data**, which the SDK performs itself via `GET /api/v1/chat/export` — no host hook. Dismissing Privacy cancels an in-flight export; the temp JSON is deleted after share or dismiss. |
| `contextProvider` | no | Resolved on every send (AI context) **and** once at `makeView()` bootstrap for start-prompt `url_pattern` matching **and** `GET /api/v1/chat/banners?url=` (literal substring / server schedule). Include a path or URL (e.g. `/products` or `https://shop.example.com/products/123`) if patterned chips or banners should appear; a SKU-only string will not match dashboard URL patterns. `nil` / empty → global (null-pattern) prompts / all-page + default banners. |
| `onOpenLink` | no | Receives links tapped inside a reply. Absent, the URL opens in the browser and the user leaves the app. |
| `onClose` | no | Receives the visitor's close action after an optional rating prompt. When set, the SDK shows a close button; absent, there is no SDK close control (the host owns dismissal exclusively, as before). If livechat CSAT is on screen, Close skips that overlay (no POST) then calls `onClose`. |
| `onAddToCart` | no | Receives an add-to-cart tap on a product card (`AIChat.ProductSelection`). The cart button only appears when this is set, `/config` reports `product_card.add_to_cart.enabled`, **and** the card carries a sku. `id` is a catalog id when the source supplies one. `sku` is untrusted — validate it against your catalog before calling a cart API. The SDK does not show "added" feedback. Absent → open-product only. |
| `onLivechatSessionChange` | no | Receives `AIChat.LivechatSessionInfo` when livechat **status** or active **agent name** changes (not typing / messages). Use the last value for a launcher badge or re-present. The poller still parks when the sheet is dismissed or the app backgrounds — not a live dismissed feed. Absent → no-op. |
| `conversationFlow` | no | `.topDown` (default) lifts the sent message to the top and streams the reply beneath it; `.bottomUp` is a classic chat that follows the newest turn. |
| `apiBaseURL` | no | Chatbot API host. Defaults to `DivergeAPI.productionBaseURL`. Pass a non-production URL from the host or sample build settings while integrating (e.g. `https://dev.api.dialogintelligens.dk`, `http://127.0.0.1:3000`). |
| `attachments` | no | `.photoLibrary` (default) shows an attach control that opens the system photo picker; one photo per message. `.disabled` hides it — use this when the chatbot's flow is not set up to receive images (the API does not yet tell the SDK, so this is the host's call). |
| `rating` | no | `.enabled` (default) presents a 1–5 **conversation** rating overlay (`POST /rate`) on close when the conversation has a user turn; `.disabled` closes immediately. Only takes effect when `onClose` is set. `hasRated` is per `AIChat` instance. Does **not** gate livechat CSAT (`POST /livechat/feedback` when the server reports `feedback.pending`). |
| `appearance` | no | `.system` (default) paints `/config`'s `theme` or `dark_theme` from the environment color scheme. `.light` / `.dark` lock the slot — `.dark` does not invent a dark look. Unconfigured chatbots stay visually light under `.system` (in Dark Mode) and under `.dark` (server clones light into `dark_theme`). Chrome (keyboard, pickers) follows the painted palette, not the lock alone. Captured on the first `makeView()`; mint a new `AIChat` to change it. |

Start-prompt chips (`start_prompts` on `GET /config`) and in-chat banners (`GET /api/v1/chat/banners`)
use that same `contextProvider` string. Matching / fetch is bootstrap-time only — not on every send,
and not while the visitor navigates with the chat still open. Hosts that want per-page chips or
banners should return a URL or path, the same way the web widget sends the real page URL. The Sample
app's **Page / URL** field is the recipe.

## Breaking changes

None — this is the initial public surface.

## Migration steps

1. Add the SPM package dependency (prefer a SemVer pin / GitHub Release tag).
2. Implement `tokenProvider`, `resetConversation` and `deleteData` against your auth and privacy backends.
3. Present the view or view controller; the host owns presentation and dismissal. To let the SDK
   offer a close button (and optional rating prompt), pass `onClose` that dismisses your
   presentation — e.g. `onClose: { session = nil }` for a SwiftUI `sheet(item:)`.

   If you present in a **sheet** and want the rating prompt, disable interactive dismiss
   (`.interactiveDismissDisabled()`) or intercept dismiss yourself. A swipe on the host sheet
   never goes through `onClose`; the SDK does not hook UIKit sheet gestures.

   `hasRated` is in-memory on the `AIChat` instance. Keep that instance if the session (and
   “already rated”) should outlive the sheet. Hosts that mint `AIChat` on every present will
   re-ask — that matches the web widget.

   Livechat CSAT (`POST /livechat/feedback` when `GET /livechat/state` reports `feedback.pending`)
   ignores `Configuration.rating`. If that overlay is on screen, Close skips it (no POST) then
   calls `onClose`.

   The livechat waiting-room form (`trigger == livechat_waiting` on `/config.forms`) is SDK-owned.
   There is no host gate: Save PATCHes `/api/v1/chat/forms/{id}/values` while the visitor stays in
   the queue. `Configuration.attachments` does not apply (string fields only; `file` is omitted).

## New permissions / privacy

- Info.plist: none required — see [`Docs/privacy/`](../privacy/). The photo attach control uses
  `PhotosPicker`, which runs out-of-process and needs **no** `NSPhotoLibraryUsageDescription`; do
  not add that key for the SDK, it would only trigger an unnecessary permission prompt.
- Privacy Manifest: `Sources/AIConversation/PrivacyInfo.xcprivacy` declares no tracking and no
  required-reason API use. It declares two collected, linked data types for app functionality:
  `OtherUserContent` (typed messages, the optional context string, and close-rating free-text
  feedback, sent to the assistant backend
  to generate replies) and `PhotosorVideos` (photos the visitor attaches in the composer, downsampled
  and re-encoded on device — GPS location, capture time and device make / model are dropped, only
  pixel dimensions remain in the EXIF block — and sent to the same
  backend). Xcode aggregates SDK manifests into the app's privacy report, so your App Store
  Connect **App Privacy** answers should list "Photos or Videos" as collected unless you pass
  `attachments: .disabled`.
- Livechat (human agent) needs **no host API**. When `/config` reports livechat enabled, the SDK
  shows a toolbar control (if `show_livechat_logo`) and/or a `request_human_agent` marker card.
  While the visitor is **waiting**, messages still go to the AI; once an agent joins (**active**),
  sends go to livechat. Queue notes, agent turns, agent typing, and the optional waiting-room form
  (`livechat_waiting` on `/config.forms` — string fields only) are SDK-owned. Polling pauses
  when the chat is off-screen or the app leaves the foreground. While an agent session is
  `active`, the composer attach control follows `/config` `livechat.attachments_enabled`
  (host `Configuration.attachments == .disabled` still wins). Receiving agent attachments
  already works via the shared incoming mapper.
- The SDK caches the remote font asset under `Caches/` keyed by its content hash. One font is kept at
  a time.
- ATT: SDK does not request tracking — see [`Docs/site/att.html`](../site/att.html)
